# РС-10 — наблюдение и подготовка пилота

Локально реализован режим правила `observe`. Он сохраняет предварительное решение,
но не создаёт бизнес-очередь, не резервирует сотрудника, не продвигает round-robin
и не назначает ответственного. Исполнение принадлежит backend; открытый браузер не нужен.

## Работа в интерфейсе

В настройках группы выбрать «Наблюдение — без назначений». Новое правило создаётся
в этом режиме и с выключенным запуском. Сохранение использует expectedRevision;
409 сохраняет черновик, неизвестный режим источника нельзя записать как рабочий.
Совместимый старый ответ без executionMode не подтверждает поддержку переключателя.

Журнал показывает ответственного при историческом CRM чтении и отдельно предлагаемого
сотрудника. Это предложение, а не результат назначения. Дата записи, причина, следующая
смена, эпоха и версии доступны в записи. Страницы ограничены 25 строками; offset в URL.
Пустая страница означает отсутствие видимых строк только в этой области: сервер может
скрыть строки без прав. Ошибка источника и неполный HTTP200 показаны ошибкой, а не нулём.
При недоступном справочнике имена CRM не подтверждаются; записи остаются отдельно доступны.

Переключение observe → live устанавливает новую границу. Прошлые наблюдения не исполняются;
новые входы после границы могут ожидать возобновления, если правило приостановлено.
Сервер отказывает переключению при незавершённой рабочей очереди. Обычная пауза/возобновление
в live сохраняет ранее принятую очередь. Настройка режима не отменяет неизвестные эффекты.

## Доказательства и ограничения

TeamOS UI: 399 unit-тестов, сборка/контракт, lint без ошибок (5 прежних предупреждений),
11 браузерных сценариев и дополнительная проверка malformed200/неизвестного решения/
отказа справочника. HTTP перехватывается Playwright; это проверка UI, а не живой amoCRM.
Снимки нового observe-сценария: desktop 1280×720 и ночь 390×844, сохранены отдельно.
Прежние браузерные сценарии также проверяют ширины 1440/390.

Каноническая матрица и проверка настоящих локальных Core↔TeamOS сервисов находятся
в amocrm-pro: `docs/specs/lead-distribution-v1/11-local-acceptance.md`.
Порядок пилота, stop/rollback и расширения — `docs/runbooks/lead-distribution-pilot.md`.
Эти материалы отличают реальный локальный транспорт/две БД от CRM/SDK fixtures и live gate.

## Следующее окружение

Сначала изолированный сервер с CRM fixture: точные версии, отдельные БД, TLS,
приватный транспорт, миграции, роли, рестарт и проверенный backup/restore.
Рекомендуемая живая приёмка: тестовый сервер + отдельный аккаунт amoCRM,
тестовая интеграция, HTTPS домен, 2–3 сотрудника и искусственные сделки.
Установить pinned ZIP и сверить общие настройки из TeamOS и amoCRM.
Проверить G1–G6 канонического runbook до разрешения live выбранной группы.
Быстрая альтернатива — локальные сервисы с HTTPS tunnel; ноутбук должен оставаться доступен,
наружу только callback/widget API, admin/private transport закрыты.
РС-03.1.2 (OAuth) и РС-08.3.2 (установленный ZIP/SDK) остаются живыми зависимостями;
локальная работа не выполняет реальное переключение старого распределителя.
