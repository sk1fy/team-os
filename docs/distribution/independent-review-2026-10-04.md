## Исправленные замечания

- **P1: включение группы до сохранения режима.** При paused группе и active live правиле сохранение observe + включение сначала отправляло `configureGroup(active=true)`. Worker мог увидеть промежуточную live-конфигурацию. Теперь сначала сохраняется paused группа, затем правило/режим, затем отдельное включение с revision ответа первой записи. После подтверждённой паузы конфликт/ошибка записи правила не включает группу. При потере ответа последнего включения его результат проверяется отдельно. Чекбокс учитывает обе активности: группы и правила.
- **P1: неизвестное действие теряло идентификатор при отказе повторения.** После потери ответа последующий 401/403/404/409 не доказывает отказ первой попытки. Recovery теперь сохраняет исходные тело/requestId при любом неуспешном ответе и блокирует замену новым действием. Сообщения и pending привязаны к queue item; закрытие диалога не сбрасывает выполняющийся запрос.
- **P2: отсутствующий режим.** Источник без executionMode больше не отображается выбранным live в редакторе; показывается неподтверждённый режим, запись этого поля запрещена.
- **P2: кешированные закрытые данные после отзыва прав.** Фоновый 401/403 раньше оставлял группу и редактор видимыми. Теперь интерфейс скрывает кешированные данные при отказе доступа. Обычный 503 по-прежнему сохраняет черновик.

## Ограничения

Проверки UI используют локальные синтетические HTTP-ответы и не подтверждают настоящий OAuth/SDK/назначение amoCRM. Исходные live gate РС-03.1.2 и РС-08.3.2 остаются отдельной приёмкой. UI не снимает guards/claims и не заменяет серверное выяснение истёкшего назначения. Исправление Core/Team backend для безопасного no-attempt expiry использует существующие queue states и reason `decision_recalculation`; attempted unknown остаётся неопределённым до подтверждения.

Идентификатор невыясненного UI-действия хранится в памяти QueryClient в отдельной области текущего пользователя, переживает смену маршрута и временный отказ доступа. После полной перезагрузки необходимо проверить текущее серверное состояние; отсутствие повторных CRM effects обеспечивает серверная модель idempotency/guards, а не браузерное хранилище. Production и реальная интеграция не менялись.
